### Fixed
- `unio lead-session effort show` and `status` mark an active `outcome_unknown` attempt as `delivery uncertain, effective Unknown` and an unacknowledged one as `delivery not yet acknowledged`. Neither is shown as an ordinary confirmed active turn. JSON `current_request.delivery` adds `accepted`/`pending`/`uncertain`.
- `waiting` is truthful. It clears after a completed turn once every registered worker is terminal and no review wakeup remains, under the short control lock. A real concurrent wait on a non-terminal worker stays visible. Views make no calls.
- `unio lead-session start` refuses to replace an owner whose record or control state is unreadable or unknown, without resetting anything. It also refuses a stopped owner that still has a proven unresolved active turn, pointing to same-thread `recover --session <id> --interrupt`. Both checks run before any new process or inference.
- `lead-session` bash completion offers `recover` and the current documented flags.
- Tests: the project-root test expects the public `mode: fast` output, while stored schema-1 `yolo` is unchanged. The branding completion check expects exactly `--preview` and then `--json` for `verify`, and names each failed condition instead of exiting silently under `set -e`. The display suite now counts the real `<session>.rpclog.jsonl`. It also writes its fake behavior sidecar as 0600 regardless of umask. This fixes the original native-verify `held_code == 6` failure: umask 022 produced a 0644 sidecar, the product correctly refused it and the run exited 3. A vacuous `or True` check is replaced with exact wakeup consumption.
- Docs: the display guide cites the existing V8 contract and uses a real model id. The starter comment no longer calls AUTO the effort. The bridge docs note the intentional V7 mapping-capacity `rejected` exception to legacy defaults.
