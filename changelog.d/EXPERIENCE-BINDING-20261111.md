### Changed
- Experience recording around integration now provides precise actionable diagnostics instead of the generic `native result has no current revision binding` error. When the base commit on `main` advances after task completion while candidate commit, task definition, and worktree bytes match, `unio experience record` refuses with: `base advanced since task execution; record experience before integration; old evidence remains historical for the prior base`.
- Worker drift (`candidate_commit` changed), task drift (`task_sha256` changed), and material drift (`worktree_sha256` changed) are now reported with dedicated actionable diagnostics (`worker drift: candidate commit changed since execution`, `task drift: task definition changed since execution`, `material drift: worktree changed since execution`), distinct from missing (`native result has no current revision binding`) or malformed (`malformed native revision binding`) bindings.
- Preserved strict schema-1 integrity, exit code 2 on stale evidence, and zero-provider boundaries without weakening stale checks, fabricating freshness, or creating synthetic acceptance. Documented that recording historical evidence on moved bases requires a separate explicit contract and schema design as a future follow-up.
### Added
- Meaningful test coverage in `tests/unio-model-experience.py` covering the real installed native Unio fixture integration sequence (`test_15_real_installed_integration_sequence`), along with unit test coverage across all revision drift, base advancement, and malformed binding diagnostics (`test_14_revision_drift_and_diagnostics`).
