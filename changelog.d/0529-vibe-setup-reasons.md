### Added
- The optional Mistral Vibe adapter now records a bounded `setup_reason` on native `usage_error` and `config_error` exports, and prints a fixed `Vibe setup:` operator line, so an unavailable requested alias or a rejected native argument is visible without opening the private export. Recognized "Unknown model: ALIAS" messages emit only an allowlisted alias or wire name from the adapter pins; recognized argparse-style native argument errors emit only an allowlisted flag. Arbitrary `error.message` text, available-model lists, URLs, paths, credentials and session identifiers are never copied. Malformed, oversized or unsupported errors stay `unknown`. Actual process/adapter/native exits, Unknown usage and effective identity, and cap/quota/timeout classifications are unchanged. Adapter-outcome still labels these Setup failure. `docs/integrations/MISTRAL-VIBE.md` has no setup-reason section, so it was left unchanged.
