# 0.5.30 first slice: attached report reviews, without approval promotion

Owner-authorized Fable R03 follow-up. Baseline official0.5.29/65d2a2975d71adb16362f33ac0f6e06027d378fd. This behavioral contract supersedes conflicting parts of earlier Grok/Gemini proposals. It is a bounded first slice, not all R03 or automatic acceptance.

## Purpose and boundary

Make a separately assigned report-only code review discoverable against its target task and exact supplied material. Preserve Source exit/delivery/validation, declared coverage, semantic verdict, findings format, material freshness, context and human acceptance as separate facts. Supplied material is not proof of model attention or effective identity. All existing native review receipts, `reviews` default/findings/projection, `review_current`, result readiness, owner acceptance, Source/commit/no-op gates, account groups and evidence remain unchanged. No UI work, broad policy migration or new provider execution path. No automatic scoped-to-whole aggregation.

## Interfaces

1. `unio review-packet <target-worker> <target-task> [--path PATH ...]` prepares bounded local material without provider calls. It prints JSON containing a new32hex packet ID, manifest SHA256 and a copyable task declaration. Default coverage label `task_material`; explicit repeated paths label `paths`. Those labels describe supplied material/declaration, never whole-app approval. Explicit paths must be safe relative paths relevant to the target material, no globs or scope expansion.
2. The separately authorized reviewer task MUST contain one exact active `## Review packet` section with one fenced JSON object: `{"schema_version":1,"id":"<32hex>","manifest_sha256":"<64hex>"}`. Native Source already freezes its effective prompt and dispatch hashes before invocation. Bind reads this declaration from validated native predispatch evidence, not current prose/output/target.json. Duplicates, malformed sections, missing original binding or post-dispatch additions refuse. Do not change the existing agents.conf command surface or rewrite an active prompt after binding.
3. `unio reviews-bind <target-worker> <target-task> <source-worker> <source-task>` attaches ONE verified review. Coverage is taken exclusively from the frozen packet/declaration; no caller override. Zero provider calls and no account slots. No changes to target worktree/result acceptance.
4. `unio reviews <target-worker> <target-task> --reports [--json]` is a SEPARATE observational view. Existing invocations and canonical projections are byte/semantically unchanged. Report views explicitly say no native-readiness or human-acceptance effect. `--findings` combined with `--reports` may refuse clearly rather than mix contracts.

## Trusted material chain

Private bounded `coord/review-packets/<id>/manifest.json` plus material text files. Use the existing target verification/snapshot/material primitives and limits (native protocol2 material, clean committed text target, supported state, current verifyPASS); avoid a second diff generator. Store target worker/task/four-field revision, material protocol/hash/size and declared paths/coverage. Capture exact supplied material bytes, not only live filenames or a hash recalculated at import. IDs/paths confined to owned project namespace; strict regular files/no symlink traversal, stable bounded reads, modes/identity/digests, exclusive/atomic publication. Do not capture ignored files, secrets/auth, unsupported states or arbitrary external paths. Existing native material safeguards stay authoritative.

Packet is created BEFORE reviewer Source. The packet ID+manifest hash must occur in the source's native-frozen predispatch task/prompt, whose original task, command, attempt/run and artifact bindings pass existing native validators. This predispatch declaration is the time anchor; a reviewer-created manifest/target assertion or hash computed only at bind is NOT sufficient. Compare packet bytes/digests and target live revision/material at bind and on later view. Refuse mismatches rather than make old0.5.29 reports artificially fresh. Exact files supplied do not prove a model read them; do not describe this as remote attestation or whole-host tamper proof.

## Eligible Source and report format

V1 requires a current idle report-only source task: actualSource0, native validationPASS and complete immutable required delivery. Require named native artifacts `summary.md`, `verdict.json` (closed `{schema_version:1,verdict:APPROVE|REQUEST-CHANGES}`) and `findings.json` (reuse current typed findings schema). Strict bounded JSON, duplicate keys/nonfinite/invalid types refuse; no arbitrary artifact path argument. Keep semantic verdict and typed findings completeness independent from native footer/fence status. Do not fabricate protocol2 stdout or normalize an original stream. Nonzero/incomplete/malformed/stale sources refuse attachment with actionable reason; their original files/results remain untouched. Observational attachment of failed source is a later slice.

Preserve actual source route command/task/attempt/artifact digests and requested/effective Unknowns from validated evidence. Do not infer AI lab or effective model from alias/account/AutoBalance. Config/command drift must remain visible/conservative according to existing source validators; never mutate config or relabel accounts to force a bind. Exact per-run source route configs may need to be supplied when reading those sources; document the supported context rather than weaken identity checks.

## Store and views

Dedicated `coord/reports/<task>.report-review.<id>/` namespace and independently typed receipt. NEVER mint a legacy approved `.review.XXXXXXXX/receipt.json`. Prove actual0.5.29 readers ignore these directories and retain original decisions/readiness. Copies/pointers of validated source artifacts must be bound, stable and bounded; source mutations later invalidate freshness. Record target snapshot/material, packet hash, source attempt/command/artifact identities, semantic verdict, findings format, declared coverage, current/stale/incomplete and `human_acceptance:false` / `native_readiness_effect:none`. Deterministic idempotency key: exact target+packet+source attempt/artifact evidence. Replays are no-op, no evidence overwrites. Same-revision REQUEST-CHANGES remains alongside later APPROVE; scoped reports never aggregate into full approval. Defend bounds and malformed/corrupt receipt history conservatively.

Hold/refuse native target and source busy states with existing lock paths and safe ordering; no deadlock or provider call. Preserve STOP: read-only report view works during STOP; packet/bind writes refuse STOP before work/publication in this first conservative slice. No owner grant, slot, lead/tier/account mutation. Atomic local evidence publication; no claimed global exclusion of unmanaged host writers.

## Implementation shape

Prefer importable `tools/report-reviews.py` with a focused embed helper and thin CLI/native-quality bridge reusing existing validators. Do not inline another large independent validator engine or change native review/result projections. Keep generated installer reproducible. Add CLI help/completion, user guide, changelog fragment. Source behavior may be split into internal helpers but ONE coherent worker assignment; no recursive models. If native validators cannot supply a sound predispatch anchor, deliver an honest blocked contract gap and partial committed work, not an unsafe alternative.

## Meaningful regression evidence

Exercise actual commands with offline mock/native fixtures; no real provider or global writes. Positive packet->frozen reviewerSource->bind->view, idempotency and separate semantic/format facts. Run actual pre-change0.5.29 reader against new namespaces proving decisions/readiness unchanged. Negative cases: old source with no predispatch declaration; duplicate/malformed/late declaration; forged/import-time packet; packet/target/task/command/source/artifact drift; wrong target/project; nonzero source/ack-only/missing report; malformed typed JSON; existing symlink/nonregular or oversize material; unsupported Git state; stopped/busy target/source; publication interruption; REQUEST-CHANGES retained after approval; multiple scoped reports do not promote; default native review/findings/result interfaces unchanged. Tests must not rewrite bound artifacts, and permission probes explicitly chmod expected modes rather than depend on umask.

Focused tests during implementation; one full quality gate at release after independent other-lab review and lead assessment. No whole-Fable completion, token-saving or universal model-quality claim. Explicit owner acceptance/UI, automatic lab eligibility, profile dispatch/metadata, other model adapters, policy migration and engine rewrites deferred.
