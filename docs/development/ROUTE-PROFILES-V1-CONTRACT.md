# Route profiles V1 implementation contract

An optional route profile is a reusable launch recipe. V1 compiles the existing canonical adapter command; it does not replace agents.conf, dispatch/admission, receipts, validation, review or owner consent. Requested model/effort/version/lab are declarations; effective values and remaining allowance stay Unknown. Account mappings and budget slots remain current native policy, never profile claims.

Initial supported compilation is the tested packaged Vibe3.1.1 / glm-5-3 path. Other providers and arbitrary wrapped commands remain legacy routes, not falsely supported profile targets. Dynamic provider availability still may refuse a correctly constructed command. High requested thinking is catalog metadata on Vibe3.1.1, not a proven native per-run effort control. Existing model/version pins are unchanged.

Public command: `unio routes` and `unio routes --json` list optional declared profiles; `unio routes show NAME [--json]` displays one; `unio routes compile NAME` prints exactly one safely quoted agents.conf entry. No automatic file writes, profile execution, credential access, sign-in, quota probing, CLI installation/version subprocess or configuration update. Works under STOP and outside a project. Missing optional file means empty inventory. An invalid file/name/action fails with actionable bounded diagnostics before any provider call.

Registry path: `$UNIO_CONF_DIR/route-profiles.json` (ordinary configured CONF_DIR fallback). No project override in V1 to avoid ambiguous precedence. Closed JSON schema_version1 with routes map. Each route name is a usable native agent prefix: lowercase first letter, then lowercase letters/digits/underscore, at most64characters and no hyphens. A hyphen separates worker suffixes in existing native lookup and cannot be part of this V1 compiled alias. Route fields must declare adapter=vibe, requested_cli_version=3.1.1, model=glm-5-3, thinking=high (or another exact supported documented Vibe choice), receipt_dir=absolute existing-parent destination declaration, and optional numeric/none caps supported by current canonical adapter. The implementation owns final field spelling/schema example in docs/integrations/ROUTE-PROFILES.md, keeping this behavior. Unknown keys, duplicate keys, unsupported schema/types/nonfinite numbers, oversized/nonregular inputs, NUL/control/injection strings and unsupported adapter/model/version refuse. Receipt_dir is a safely quoted path, not a command; spaces and shell punctuation must be handled safely, with no read of secrets or any side effect. Do not silently normalize invalid values or supply unapproved fallback. Compilation must refuse control-containing configuration/executable paths with a fixed bounded diagnostic rather than print an entry spanning physical lines. Normal spaces/quotes/metacharacters still roundtrip.

Compile from trusted installed adapter path under actual CONF_DIR/lib/adapters/vibe-worker.py, using current adapter parser/check_bounds as the authoritative accepted limits; do not duplicate stale cap maxima. Optional omitted/null caps map to explicit adapter-supported none only for3.1.1; omitted versus unknown/effective remains clear. Config field values must not select executable/module imports. Load trusted packaged sibling source only with isolated interpreter (-I -S -B), never cwd/PYTHONPATH or profile-provided code. Do not assume a declared CLI pin proves installed version. Do not execute printed commands in tests except controlled offline sentinel/argv inspection. Current agents.conf parsing and runtime safety behavior remain byte/functionally unchanged.

Tests cover list/show/compile, safe paths with spaces/metacharacters, limits at bounds/outside, optional caps, malformed/duplicate/large/nonregular JSON, unknown fields, errors without echoing secret-like values, no subprocess/provider/config writes even under STOP/outside project, hostile cwd/PYTHONPATH, standalone installer exact helper bytes and unchanged legacy route syntax. All fixture installs require explicit isolated UNIO_BIN_DIR, UNIO_CONF_DIR, UNIO_COMPLETION_DIR and project-owned TMPDIR. No auth, billing or global install in tests.

Scope ownership: profiles worker owns new tools/route-profiles.py, new tools/embed-route-profiles.py, tests/unio-route-profiles.py, this feature's docs/fragment and native command/help/dispatcher/packaging region. Neutral-defaults worker owns embedded MASTER block, docs/WORK-MODES.md plus its generated template, tests/unio-neutral-startup.py and its fragment. No shared authored helper/doc edits. Installer is a shared generated/disjoint-region composition artifact; preserve all other markers. Profiles worker is sole tools/quality-check.sh owner and wires both frozen new test names plus new embed --check, removing no existing checks. Full gate runs only on composed candidate; individual native gates run own focused checks. No version bump/source merge/release by workers.
