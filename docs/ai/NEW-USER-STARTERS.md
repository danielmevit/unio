# Try Unio on a new project

[Unio on GitHub](https://github.com/danielmevit/unio)

These prompts are for a separate project, not a takeover of an existing lead.
They assume the experimental managed-lead effort controls are available for
testing. Official0.5.30 does not include those controls. Check the actual installed
version and supported commands; a prompt alone cannot enable or change the
reasoning effort of an unmanaged CLI. Requested effort is not proof of effective
effort. The first adaptive interface uses AUTO, LOW and XHIGH only.

## One subscription

```text
Help me try Unio on this project: [PROJECT PATH].
My goal is: [SMALL FEATURE OR FIX].
I have one AI subscription: [SUBSCRIPTION / CLI].

Check the installed Unio version and project instructions. Set up a small
end-to-end trial with a task file, isolated worker worktree, meaningful checks
and a clear handoff.

Use managed-lead AUTO effort: LOW for routine coordination, XHIGH for planning,
difficult reasoning and final review. Wait without making lead model calls while
the worker runs. Verify these controls work; report unavailable controls honestly.

I authorize ONE implementation worker on my subscription beside the lead.
Preserve the real shared-account mapping. Use the explicit native grant and
narrow temporary coordination tier needed, then restore the previous tier when
idle. Start the worker at its lowest supported effort; increase it only for
reasoning difficulty. No extra workers or paid API fallback.

Review the result yourself. State that independent cross-lab review is
unavailable; preserve stricter project approvals. Give an estimate, brief updates
and an honest final result. Keep changes local for this first trial.
```

This explicitly permits two workflows on one shared subscription: lead plus one
worker. It does not create extra allowance. Without that exception, keep one
active workflow and use a sequential handoff. Coordination tier and reasoning
effort are separate settings.

## Multiple subscriptions

```text
Help me try Unio on this project: [PROJECT PATH].
My goal is: [FEATURE OR FIX].
Available subscriptions and CLIs: [LIST THEM].
You are the lead; use other eligible subscriptions as workers.

Check the installed Unio version, project instructions and available routes.
Use YOLO delivery with low coordination tier: one workflow per shared
subscription, including the lead. Preserve actual mappings, holds and STOP.

Enable managed-lead AUTO effort: LOW for routine coordination, XHIGH for
planning, difficult reasoning and final review. Wait without making lead model
calls while workers run. Verify effort controls work; distinguish requested
settings from effective Unknowns.

Delegate focused tasks through Unio in isolated worktrees. Run independent tasks
concurrently when scopes and budgets permit. Use appropriate supported worker
effort, escalating for reasoning difficulty, not network, auth or quota failures.

Inspect real code and meaningful tests. Obtain one independent review from a
different AI lab, then perform your final assessment. Preserve failures and
partial work; never manufacture approval. Honor stricter project approvals.

Use included subscriptions only. Give estimates and brief updates explaining
the goal, progress and next step. Keep changes local for this first trial.
```

These generic examples do not lift routing holds in an existing project or
prove login, model identity, remaining allowance or successful delivery.
