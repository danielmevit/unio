# Reviewer-led corrections when Sol struggles

Owner clarification recorded 2026-10-24T11:07:22+02:00. This is lead routing guidance, not an
implemented automatic switch or a request to change an active run's effort.

Sol remains the default correction worker. When Opus identifies a concrete
issue and repeated Sol corrections fail to resolve that issue, assign ownership
of the remaining fix to Opus. This is conditional; an Opus finding alone does
not reroute every task. Preserve an active Sol assignment through completion or
a safe handoff, including its commits, failed attempts and receipts. If its
current patch resolves the issue, use the normal review path rather than
manufacturing an extra fix.

For an Opus takeover request Claude subscription / Claude Code / Opus5.5 at
LOW first. If the actual result shows a reasoning gap, increase one supported
step: low, medium, high, xhigh. Preserve each attempt and the evidence for the
choice; frozen runs retain their settings. Max/ultra and paid fallback are not
authorized. Quota, authentication, connectivity and setup failures are not
reasoning gaps and do not justify raising effort.

The lead scopes and delegates one bounded task through Unio, preserving real
account mappings, lead reservation, owner holds and STOP. CLI/version, requested
model/effort, observed results, checks and effective Unknowns remain explicit.
Workers do not spawn recursive reviews or agents. A verified already-fixed
candidate requires an honest no-change report, not an artificial commit.

Keep final review independent. If Opus authors the repair, choose an eligible
reviewer from another AI lab for the current corrected code; the existing lead
still provides final assessment. Keep the personal default of one external
reviewer plus the existing lead. A repair is not its own independent approval;
old rejected/stale reviews remain unchanged. Read the current owner workflow
before assignment and acceptance.
